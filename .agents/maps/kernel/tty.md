## Responsibilities

`kernel/tty` implements pseudo-terminals entirely inside the kernel layer:

- PTY pairs: allocation through `/dev/ptmx`, opening slaves, `/dev/tty` and `/dev/console`,
  `TIOCGPTPEER`, closing, hangup and `vhangup`;
- the line discipline, a port of Linux's n_tty (input mapping, canonical editing, echo, flow
  control, signal characters, output processing, `VMIN`/`VTIME`) and termios/termios2;
- packet mode;
- job control: controlling terminals, sessions and foreground groups, background-access checks,
  terminal-generated signals;
- the host console: kernel-held masters for the app's terminal tabs and the `tuxport-run` bridge.

Root: `core/kernel/src/tty.rs`, `syscall/tty.rs`, `terminal.rs`.

Outside the module: devpts as a filesystem, instances, and the owner, mode and times shown for
`/dev/pts/N` (`kernel/procfs`); device-number dispatch on open (`kernel/files`); signal delivery,
stops and orphaned-group stop rules (`kernel/signal`); `setsid`/`setpgid`, process exit and the
exit-time orphan signals (`kernel/process`); the host terminal's raw mode and signal pipes
(`harness/cli`, `hal`); the Android terminal UI (`android`).

## Key types

- `Tty` — one PTY pair (shared by both sides): devpts device and index; `masters`/`slaves`
  counts, `slave_closed`, `locked`, `hung_up`, per-side `vhangups` generations and `hupped`;
  termios (the slave's, the only one), winsize; buffers `unprocessed` (master writes not taken by
  the line discipline yet: Linux's flip buffer, 64 KiB), `editing` (canonical line being edited),
  `lines` (finished lines, each `Line` with data, whether VEOF ended it and whether that VEOF is the
  host console's end of file), `raw` (non-canonical and EXTPROC queue), `echoes` (waiting `Echo`
  operations), `output` (waiting for the master, 64 KiB); cursor `column` and `canon_column`;
  `lnext`, `erasing` (an open ECHOPRT erase), `signals` generated by input; flow state (`stopped`,
  `tco_stopped`, `master_stopped`), packet state (`packet`, `pktstatus`); `session` and `fg`;
  owner, mode, times; edge counters `arrivals` (what the slave reads, what the master reads).
  The pure line discipline lives here; blocking, `VMIN`/`VTIME` timing, signal delivery and job
  control are in `syscall/tty.rs`.
- `Echo` — one echo operation of Linux's echo buffer: a character through output processing, a
  `^X` pair, backspaces over an erased tab, setting the line's start column, one column back.
- `PtyEnd` — one open end: the `Tty`, master flag, mount, `pin` (keeps the devpts mount busy),
  `born` (the side's vhangup generation at open). Opening and dropping it maintain the counts (and
  opening a slave re-arms the slave side's vhangup); dropping the last master queues the terminal
  on `CLOSED`, and every drop wakes the terminal's waiters.
- `Termios` — kernel termios2 layout (four flag words, line, 19 control characters, input and
  output speed); `flags`, `cc`, `pkt` constants (a subset of Linux's); `Winsize` (24×80 by
  default, as consoles start; a new PTY is 0×0).
- `Kernel::ptys` — `(device, index) → Weak<Tty>`; the thread-local `CLOSED` list of terminals
  whose last master closed.
- `terminal::Console` (a kernel-held master and whether a session was ever attached) in
  `Kernel::consoles`; `terminal::Terminal` (the host fds the bridge uses: input, output, the fd
  whose size it follows, the resize pipe).
- `ThreadGroup.ctty` (a strong reference, so a controlling-terminal link keeps the terminal alive)
  and the session leader's `tty_old_pgrp` (in `kernel/process`'s structures) link processes to
  their controlling terminal.

## Public entry points

- Opening (from `kernel/files`' device dispatch): `open_ptmx` (which allocates through `new_pty`),
  `open_slave`, `open_peer` (`TIOCGPTPEER`), `open_ctty` (5:0 and 5:1).
- I/O: `syscall::tty::read`, `write`, `readiness`, `ioctl`.
- Hangup: `hang_up`, `vhangup_ctty` (`vhangup(2)`), `hang_up_closed` (run when the BKL is
  released).
- Host console: `terminal::{open, attach, detach, wake_objects, take_output, take_output_run,
  input_room, feed, fg_pgrp, fg_cwd, password_input, resize, close, initial_size, bridge}`,
  wrapped by `Machine::{open_console, read_console, read_console_run, write_console,
  resize_console, close_console,
  console_foreground, console_cwd, console_password_input}`,
  `Stdio::Console` at spawn and the kernel's `run`.

## Data flow / lifecycle

### Allocation and opening

- `/dev/ptmx` → `new_pty`: drop dead table entries, read the instance's options, `ENOSPC` at
  `max`, take the lowest free index, owner from the options or the opener's fsuid/fsgid, mode
  from the options. A new terminal is locked with winsize 0×0; the master end makes `masters` 1.
- Master-only ioctls: `TIOCSPTLCK`/`TIOCGPTLCK`, `TIOCGPTN`, `TIOCPKT`/`TIOCGPKT`, `TIOCSIG`
  (INT, QUIT, TSTP; others `EINVAL`), `TIOCGPTPEER` (opens the slave through the master's mount,
  with the caller's flags and so with controlling-terminal acquisition, keeping access mode,
  `O_APPEND`, `O_NONBLOCK`, honouring `O_CLOEXEC`; on a slave or hung master `EIO`).
- Slave open: no live entry `ENOENT`; locked or no master `EIO`; without `O_NOCTTY` a session
  leader without a controlling terminal acquires an unowned terminal when the open has read
  access (Job control below).
- `/dev/tty` and `/dev/console` both open the caller's controlling terminal as a slave end through
  the boot devpts mount (`ENXIO` without one), with no lock or master checks, and never acquire
  one.

### Input (master writes, host console feed)

- A master write (or the host `feed`) goes to `unprocessed`, up to 64 KiB (`input_room`; a full
  buffer blocks the writer, returns `EAGAIN` or a short count; TCOOFF on the master makes the room
  0). The line discipline takes from it while it has room: 4095 bytes in all (finished lines with
  their VEOF, the edited line, the raw queue), and in canonical mode while no line is complete the
  room never drops below one byte, so a terminator, an erase or a signal character gets through a
  full line (the edited line keeps one byte for its terminator; other characters are dropped
  without echo). What does not fit is taken when the slave reads, termios changes or `TIOCSTI`
  injects, and signal characters then found are sent by those paths.
- Each byte (Linux's `n_tty_receive_buf_standard`): `ISTRIP`, then `IUCLC` with `IEXTEN` (Latin-1
  `tolower`); after `VLNEXT` it is an ordinary character; with `EXTPROC` it is queued raw with no
  editing or echo; bytes in the special set (`char_map`: CR/NL when translated, the editing and
  line-end characters in canonical mode, `VWERASE`, `VLNEXT`, `VEOL2` and `VREPRINT` only with
  `IEXTEN`, `VREPRINT` also only with `ECHO`, flow and signal characters; never NUL) go through
  `receive_special`, others are ordinary.
- `receive_special` in Linux's order: `IXON` (`VSTART` restarts, `VSTOP` stops); `ISIG` signal
  characters; `IXANY` restart; `IGNCR`/`ICRNL`/`INLCR`; in canonical mode `VERASE`/`VKILL`/
  `VWERASE` (eraser), `VLNEXT` (echoes `^\b` with `ECHOCTL`), `VREPRINT` (the character, a newline
  and the line), NL (echoed with `ECHO` or `ECHONL`), `VEOF` (ends the line with an EOF mark),
  `VEOL`/`VEOL2` (echoed as characters, leaving an `ECHOPRT` erase open). Anything else is queued,
  a newline echoed as itself.
- An ordinary character restarts output with `IXANY`, closes an `ECHOPRT` erase with `/`, is
  echoed (with `ECHOCTL` a control character other than tab as `^X`, so a literal newline or one
  in non-canonical mode shows `^J`) and queued; with `PARMRK` 0xff is queued twice.
- A signal character queues the signal and, unless `NOFLSH`, discards the waiting echoes, the
  output the master has not read and the input (`FLUSHREAD|FLUSHWRITE` in packet mode); input not
  taken yet stays and is still processed. Then `IXON` restarts output and the character is echoed.
- Erasing (Linux's `eraser`): nothing on an empty line; `VKILL` without `ECHO` empties the line
  silently, and without all of `ECHOK`, `ECHOKE` and `ECHOE` echoes the kill character (and a
  newline with `ECHOK`); otherwise character by character (whole UTF-8 characters with `IUTF8`, a
  stray continuation byte stays), `VWERASE` back over one run of letters, digits and underscores
  (Latin-1 included) after any other characters. The echo per character: with `ECHOPRT` `\` once,
  then the character; a single `VERASE` without `ECHOE` the erase character; a tab backspaces to
  where it began, counted from the previous tab or the line's start column; otherwise `\b \b` per
  column it took (two for `^X`, none for a control character without `ECHOCTL`).
- Echoes wait in `echoes` and are written at the end of each batch of input (a master write, even
  an empty one, a slave read that returned data, any termios change), on a slave `TIOCSTI` the line
  discipline has room for, when stopped output restarts, or before each piece of a slave write,
  through output processing with the column (`^X`, tab backspaces and an echoed 0xff bypass it).
- Each batch that hands the line discipline at least one byte counts once as an arrival for the
  slave (as do a slave `TIOCSTI` with room and the console's injected EOF); epoll re-arms an
  edge-triggered slave watcher on it, but a canonical slave is readable only with a complete line.
- `TIOCSTI` (Linux 6.1's `tiocsti`): on a slave that is the caller's controlling terminal, or with
  `CAP_SYS_ADMIN`, the byte goes straight to the line discipline, ahead of input not taken yet,
  and is dropped when there is no room; otherwise `EPERM`. A master is never the controlling
  terminal; with `CAP_SYS_ADMIN` its byte is added to what the master reads, regardless of the
  output limit. 6.2's `dev.tty.legacy_tiocsti` (off in distribution kernels, `EIO` for everyone
  without `CAP_SYS_ADMIN`) is not emulated.
- Not implemented: `IMAXBEL`, `BRKINT`/`IGNBRK`, `HUPCL`, `VDISCARD`, and Linux's lookahead of
  flow-control characters in input that does not fit yet.

### Reading on the slave

- Every slave read starts with the background check (Job control below), before looking at data.
- Canonical: one line per read. A line ended by `VEOF` returns its data without the mark when the
  buffer has room for both; a read filling the buffer exactly leaves the mark, and the next read
  returns 0 (EOF). Non-canonical: `VMIN`/`VTIME` (0/0 returns at once; 0/T times out from the
  start of the read; N/0 waits for `min(VMIN, len)` bytes; N/T waits for the first byte and then
  returns once `VTIME` passes with no new byte, Linux's inter-byte timer, waiting for a first byte
  again when another reader or a flush took what had come). With `EXTPROC` and
  `ICANON` a read returns what has arrived, as with `VMIN` 1. Slave `POLLIN` (`poll_readable`,
  Linux's `input_available_p` for poll) needs `VMIN` bytes when `VTIME` is 0 and `VMIN` above 0,
  otherwise any; a nonblocking read takes what has arrived even below `VMIN`. A read makes room
  for waiting input, and sends the signals it generates.
- No data: `EIO` without a master, `EAGAIN` when nonblocking, otherwise wait on the terminal's
  wake object. Reads update atime and writes mtime (seconds only, on 8-second boundaries).
- `FIONREAD` on the slave counts the complete lines without their EOF marks (canonical) or the raw
  queue, never the edited line or input not taken yet.

### Output (slave writes, master reads)

- Slave writes are clamped to `output_room` (0 while output is stopped, otherwise 64 KiB minus
  the queue), then output processing (Linux's `do_output_char`) with the cursor column: with
  `OPOST`, `ONLCR`, `OCRNL`, `ONOCR` (CR at column 0 dropped), `ONLRET`, `OLCUC` (Latin-1
  `toupper`), tab expansion with `XTABS`; control characters take no column, UTF-8 continuation
  bytes none with `IUTF8`. Without `OPOST` bytes pass unchanged and the column is not followed.
  `EIO` without a master; `TOSTOP` background check. A write by a process whose group is not the
  terminal's foreground group (whether or not the terminal is its controlling one; never when
  there is no foreground group) is remembered as a range of the output stream (`background`,
  against `taken`, the bytes read so far): adjacent ranges join, a read drops those it passed, and
  output discarded from the queue takes its ranges along. Echoes are never in a range.
- While output is stopped, slave writes block and echoes wait; restarting writes them. Echoes also
  go out only while the output queue has room for each whole one (`__process_echoes`); the rest
  wait for the next commit, at most 4096 of them (the oldest dropped): the next batch of input, or
  the next slave write, which sends them ahead of each piece of its data (`n_tty_write` starts
  with `process_echoes`); a master read does not send them, on Linux either. TCIOFF and TCION
  on the slave send their character even through a ^S stop (reporting `STOP` again in packet
  mode); under TCOOFF, or with the output queue full, it is lost, as Linux's `pty_write` refuses
  it.
- Master reads: a pending packet status byte is returned alone; otherwise `TIOCPKT_DATA` (in
  packet mode) plus the output. Once the slave has been opened and all slaves closed, master reads
  return `EIO` after draining and poll reports `POLLHUP`; a never-opened slave does not count, so
  reads block. `FIONREAD` and `TIOCOUTQ` on the master count the whole output queue.
- Packet status (each checked against Linux's recorded traces): `FLUSHREAD`/`FLUSHWRITE` (signal
  characters, slave flushes), `STOP`/`START` (each clears the other; a signal character, `IXANY`
  or clearing `IXON` restarts), `DOSTOP`/`NOSTOP` (when "default ^S/^Q flow" changes), `IOCTL`
  (when the old or new termios has `EXTPROC`); enabling packet mode clears stale status; pending
  status adds `POLLPRI|POLLIN`.

### Job control

- Acquire: the console's session leader gets the console at spawn; a session leader opening an
  unowned slave with read access and without `O_NOCTTY` acquires it (`session`, `fg` = its group);
  `TIOCSCTTY` (Linux's `tiocsctty`) returns 0 if already the caller's ctty, `EPERM` for
  non-leaders or callers with a ctty, steals a terminal from another session only with argument 1
  and `CAP_SYS_ADMIN` (clearing that session's links), and otherwise needs read access to the fd
  or `CAP_SYS_ADMIN` (`EPERM`). `CAP_SYS_ADMIN` counts only in the initial user namespace, so a
  sandbox's root cannot steal the terminal it was started on.
- Foreground: `TIOCSPGRP` needs the caller's ctty (`ENOTTY`, also before a bad pointer is read),
  passes the background check (an orphaned caller's `EIO` is returned as is), then `EINVAL` for
  negative values, translates through the pid namespace, `EPERM` unless a group with that id
  exists in the caller's session (also for 0 and unknown ids); because both ends share one `Tty`,
  it works on a master fd only when that terminal is the caller's ctty. `TIOCGPGRP`/`TIOCGSID`
  need the caller's ctty on a slave but answer any holder of the master (a tmux server has no
  ctty), and translate out (0 when invisible; `TIOCGSID` without a session is `ENOTTY`).
  `TIOCNOTTY` on a master is `ENOTTY`.
- Background access (`check_background`, Linux's `__tty_check_change`): applies when the terminal
  is the caller's ctty and another group is in the foreground; an ignored or blocked signal makes
  reads `EIO` and lets writes proceed; an orphaned group gets `EIO`; otherwise the signal goes to
  the caller's group and the call returns `ERESTARTSYS`. Callers: slave reads, slave writes with
  `TOSTOP`, termios sets, `TCFLSH`, `TCXONC`, `TCSBRK`/`TCSBRKP` and `TIOCSETD` from the slave
  (Linux's `tty_check_change` callers), `TIOCSPGRP`.
- Signals: line-discipline signals, `TIOCSTI`, `TCXONC` on the master, the host `feed` and
  `TIOCSIG` go to the foreground group; `TIOCSWINSZ` from either side and the host `resize` send
  `SIGWINCH` to it only when the size changes.
- Give up: `setsid` clears only the caller's link; `TIOCNOTTY` by a non-leader clears its own, by
  the leader clears the session's links and sends `SIGHUP` then `SIGCONT` to the foreground
  group; a session leader's exit with its ctty (always a PTY) sends only `SIGHUP` to the
  foreground group and clears the session, without one it sends both to `tty_old_pgrp`
  (Linux's `disassociate_ctty`).

### Hangup

- Last master close: `PtyEnd::drop` cannot reach the kernel, so it queues the terminal on
  `CLOSED`; the thread releasing the BKL runs `hang_up_closed` (a panic there is caught and
  reported), which marks it hung up, removes the table entry (the index can be reused,
  `/dev/pts/N` disappears), clears every process's link to it, records the foreground group as
  the leader's `tty_old_pgrp` and sends `SIGHUP` then `SIGCONT` to the session leader only.
- Hung ends (a slave after the last master close, either side after a vhangup): reads return 0
  (pending input discarded), writes `EIO`, ioctls `EIO` (`TIOCSPGRP` `ENOTTY`), poll reports
  everything including `POLLERR`. Between the last master close and the deferred hangup (which the
  closing thread runs before releasing the BKL, so others hardly see it), a slave read returns a
  complete line or raw input that already meets `VMIN`/`VTIME` and otherwise `EIO`, writes `EIO`,
  and poll reports `POLLHUP|POLLIN`.
- `vhangup(2)` (needs `CAP_SYS_TTY_CONFIG`, does nothing without a ctty) and `TIOCVHANGUP`
  (needs `CAP_SYS_ADMIN`), both in the initial user namespace, hang up one side by bumping its
  generation: every end opened earlier is hung; the master side discards unread output; the slave
  side also flushes input, clears packet status and detaches the session; the node stays and can
  be reopened. A side is hung up again only after a slave reopens (the master side never).

### termios ioctls

- Either side: `TCGETS`/`TCGETS2`/`TCGETA`, all `TCSETS*`/`TCSETA*`/`TCSETS2*` (CS8 and CREAD
  forced, PARENB cleared, ADDRB kept; speeds recomputed and only recorded; the `W` forms do not
  drain, `F` forms flush slave input; signals from input the change lets in are sent; the
  background check runs on the slave only), `TIOCGWINSZ`/`TIOCSWINSZ`, `TCFLSH`, `TCXONC` (slave:
  TCOOFF/TCOON; master: stops input; 2/3 send VSTOP/VSTART, on the master from the slave's
  termios into the input without a room check), `TCSBRK`/`TCSBRKP` (no-ops after the background
  check), `TIOCEXCL`/`TIOCNXCL` (no-ops), `TIOCSETD` (argument never read) / `TIOCGETD` (always 0),
  `FIONREAD`, `TIOCOUTQ`, `TIOCSTI`; other requests are counted as unimplemented paths
  (`kernel/signal`) and return `ENOTTY` (`TIOCSBRK`, `TIOCCBRK`, `TIOCGEXCL` and `TIOCGDEV` among
  them).
- `TCFLSH` follows `pty_flush_buffer`: on the slave, TCIFLUSH discards the input (taken or not)
  and TCOFLUSH only output beyond the 4095 bytes the master side has taken, both reported in packet
  mode; on the master, TCIFLUSH discards all unread output and TCOFLUSH the input not taken yet.
- Switching between canonical and non-canonical reading (`ICANON` without `EXTPROC`) ends
  `VLNEXT` and an `ECHOPRT` erase and moves queued input as Linux's `n_tty_set_termios` does: lines
  become raw data (a `VEOF` mark a NUL byte, except the host console's end of file, which becomes
  the old `VEOF` character); into canonical mode all queued data becomes one line, readable at
  once, a final NUL taken as its `VEOF`. Clearing `IXON` restarts output stopped by ^S.
- Defaults match Linux's pts `init_termios` (`tty_std_termios` without `HUPCL`); a control
  character of 0 is disabled.

### Host console

- `terminal::open` creates a terminal on the boot devpts instance (lowest free index without
  pruning dead table entries or checking the instance's `max`, unlocked, the given size, the
  default owner root:tty 0620) held by the kernel; `attach` (from `spawn`) makes the new session
  leader its session and foreground and returns one slave file installed as fds 0–2 and the ctty
  (`ENOENT` for an unknown console, `EBUSY` while the terminal has a session: a guest session
  leader that opened it first, or a live attached one; after the leader's exit it can be attached
  again); when the spawn then fails, `detach` clears that session and puts back whether one was
  ever attached.
- The host takes output (`take_output`: bytes, nothing yet, or empty once a session was attached
  and the terminal's slaves are all closed, by any process; `take_output_run`, which the app
  uses: the same, but only up to where the writer changes between the foreground group and
  another, with whether another wrote it, so the app's terminal does not take a background job's
  line feed at the shell's prompt for the shell's, android/vtcore), feeds input under `input_room`
  backpressure (`feed` delivers resulting signals), resizes (`SIGWINCH` on change), asks for the
  foreground group (`fg_pgrp`: its id as the kernel sees it, untranslated, `ESRCH` with none; the
  app drops what a program reported about its progress once another group has the terminal) and
  its cwd (`fg_cwd`, where restored tabs and new tabs start), asks whether the line discipline
  reads lines without echoing them (`password_input`: `ICANON` set and `ECHO` clear, as programs
  read passwords and Ghostty tests; the app draws a lock for the cursor then), and closes (drop
  the master, hang up
  immediately, so the number is free again at once, lowest-first, for consoles and `/dev/ptmx`).
  `write_console` keeps feeding input after the attached session has ended and fails with `EIO`
  only when the input room is 0, which in canonical mode without a complete line never happens.
  Host threads take the BKL and wait on the terminal's wake object like guest threads; a panic in
  a console read, write or resize closes the console and returns `EIO`. A kill report names the
  console of the killed process's controlling terminal.
- `bridge` (`tuxport-run`'s `run`, on its own thread): `tuxport-run` puts the host terminal in raw
  mode and sets up the `SIGWINCH` pipe when stdin and stdout are terminals; the console starts at
  the host terminal's size, else 24×80 (no size fd, `TIOCGWINSZ` failing or reporting 0). Output
  goes to the host (dropped on a write error); input is read only while there is room, and any
  host read error counts as end of input. At host EOF it waits until the program has no unread
  input, then sends `VEOF` once as util-linux `script` does (`Tty::inject_eof`; nothing if `VEOF`
  is disabled). In canonical mode with nothing being edited it is an empty line marked as the
  console's, so a program that leaves canonical mode before reading it (a shell going back to its
  line editor) reads the `VEOF` character instead of Linux's NUL, which the line editor would
  insert into its line and then wait forever. The bridge stops when the console closes, the
  session ends, or the program has exited and no task is left (once output is drained); `run`
  joins it. Stop signals to `tuxport-run` reach the program through `Machine::signal`, not the
  console.

## Dependencies (inbound / outbound)

### Inbound

- `kernel/files` (open by device number, `devpts_beside`, read/write/ioctl dispatch, devpts
  `nodev`), poll/epoll (`readiness`, `arrivals`), `kernel/process` (fork copying the ctty, setsid,
  exit releasing the ctty, spawn with `Stdio::Console`), `Bkl::drop` (`hang_up_closed`), the
  machine and JNI/CLI hosts (console API, bridge), the bug reporter (console of a killed process),
  procfs (stat of `/dev/pts/N`, `tty_nr`/`tpgid`).

### Outbound

- `kernel/signal` (`send_to_pgrp`, `send_to_group`, `pgrp_orphaned`, kernel siginfo, the
  unimplemented-path counter), the kernel's wake objects and `wait_objects`, pid-namespace
  translation (`pid_in`/`pid_out`), credentials (`capable`), the VFS (`devpts_options`, `path_of`,
  fd installation), `tuxport_hal` (polling, read, write, drain and `TIOCGWINSZ` of host fds, the
  clock).

## Invariants and gotchas

- One `Tty` and one termios serve both ends; the master has no line discipline of its own, and
  "is the caller's ctty" is true for either end (`TIOCSTI` and `TIOCNOTTY` single out the master).
- Hangup is never done inside `Drop`; anything that closes the last master must leave the
  terminal on `CLOSED` (or call `hang_up` directly, as console close does).
- `/dev/tty` opens count as slaves, so they affect `slave_closed` and console end-of-session.
- `session` and `fg` are bare ids, not references; a ctty link is a strong reference.
- The output limit is soft: room is measured before `ONLCR` and tab expansion, and `TIOCSTI` on a
  master ignores it.
- Input can be taken by the line discipline on a slave read, a termios change or `TIOCSTI`, not
  only on a master write, so those paths must send what `take_signals` returns.
- A signal character discards all unread output, while Linux discards only what its workqueue has
  not yet moved to the master side; the recorded scenarios (signal characters typed right after
  other input) show their echoes discarded, which this reproduces deterministically.
- A deferred hangup whose terminal has no remaining references is skipped; nothing is left to
  signal, and `new_pty` prunes the dead table entry later.
- The echo queue (`Echo`, `commit_echoes`), erasing (`erase`, `echo_erased`) and output processing
  (`output_char`) are adapted from Starnix's `lib/line_discipline` and carry The Fuchsia Authors'
  BSD-style notice in `tty.rs`'s module docs, matched by the app's notices (`android/build`).
  Code moved out of those parts takes the notice along; only a rewrite that no longer derives from
  Starnix drops it, from both places.

## Confirmed bugs / technical debt

- **One slave write can overshoot the output limit** by its `ONLCR` and tab expansion (the write is
  clamped to the room before output processing).
- **`TIOCSCTTY` returns 0 to a non-leader** whose controlling terminal it is: the "already the
  caller's ctty" test runs before the session-leader check, where Linux answers `EPERM`.
- **`TIOCSPGRP` error codes:** `EPERM` instead of `ESRCH` for unknown groups, `ENOTTY` instead of
  `EINVAL` for negative values (or `EFAULT` for a bad pointer) from a non-ctty caller, `EIO`
  instead of `ENOTTY` for orphaned callers.
- **Console input after the session ended is accepted** instead of failing with `EIO` as
  `write_console`'s comment and the JNI documentation promise; with echo on, its echoes reach the
  host after the end was reported.
- **`/dev/tty` cannot be told apart from the slave it opens:** the descriptor is a plain slave end,
  so fstat reports the pts device (136:N, with the devpts inode and owner) instead of 5:0 (5:1 for
  `/dev/console`); programs that recognise the controlling-terminal device by its number see a
  different device than on Linux.
- **Fidelity gaps:** `IMAXBEL`, break handling, `HUPCL` and `VDISCARD` are not implemented;
  `TIOCEXCL` is a no-op; `TIOCGETD` is always 0; `TIOCGEXCL` and `TIOCGDEV` are `ENOTTY`;
  `FIONREAD` and `TIOCOUTQ` on the master count the whole output queue; flow-control characters
  are not looked ahead in input waiting for room. The line-discipline rules themselves match all
  83 recorded scenarios of the `line-discipline` differential case.

## Open questions

- Is mapping `/dev/console` to the caller's controlling terminal (rather than a system console)
  intended, and should an fd opened through `/dev/tty` for a terminal of another devpts instance
  carry the boot mount?
- Should a console's end of session be its leader's exit rather than its last slave closing (a
  background job holding the terminal keeps a tab open)?
