# M9：在"文件"App 里改家目录（2026-11-02）

M9 计划的最后一轮，接着[上一轮](196-documents-read.md)的只读浏览，让 DocumentsProvider 能改登录账号的家目录：在"文件"App 里"复制到…"tuxport、新建文件夹、删除、改名、移动，别的 App 的"保存到"里也能选 tuxport。整个系统那个根仍然只读。

## 做法

### 能做什么

| 位置 | 能做的 |
|---|---|
| 家目录里面的文件 | 读、写（`w`、`wt`、`wa`、`rw`、`rwt`）、删除、改名、移动 |
| 家目录里面的目录 | 在里面新建、删除（整个目录树）、改名、移动 |
| 家目录本身 | 在里面新建 |
| 别处（整个系统那个根） | 只读 |

根上声明了能新建（`FLAG_SUPPORTS_CREATE`），别的 App 用 `ACTION_CREATE_DOCUMENT` 保存文件时、"文件"App 的"复制到…""移到…"里都有 tuxport。同一个根里的"移到…"直接改目录项（`moveDocument`），不复制。复制进来是"文件"App 先新建、再往里写；没有实现 `copyDocument`，同一个根里的复制也这样做。

### 新建的东西属于谁、叫什么

- **属主是登录账号**（`/etc/passwd` 里的 UID、GID），文件 0644、目录 0755，与 umask 022 时新建的一样。不然在终端里以这个账号改不了自己复制进来的文件。
- **名字**：用户给的照原样（UTF-8，不解 `%XX`）。`/`、NUL 换成 `_`，空的、`.`、`..` 换成 `_`，超过 255 字节是 ENAMETOOLONG。
- **已经有了**：照 Android 自己的存储那样换一个：文件是 `notes (1).txt`（扩展名留在最后，点开头的名字没有扩展名），目录是 `Projects (1)`，最多试 100 次。
- **扩展名**：新建文件时名字的扩展名与类型不符的补上（"notes"、text/plain → `notes.txt`），`application/octet-stream` 和目录不补。
- **改名、移动不覆盖**：目标已经有了就失败，与 Android 自己的存储一样。

### 只能改家目录里面的

限制按**真实路径**算（内核层的 `browse::walk` 在跟随符号链接的同时算出 realpath）：要在里面新建的目录、要删除/改名/移动的目录项所在的目录、要写的文件（符号链接跟随之后），都要在家目录的真实路径下面，经由符号链接走到外面去的是 EACCES。比如家目录里有 `etc-link -> /etc`，在 `etc-link` 里新建、写 `etc-link/motd` 都不行。删除、改名、移动作用于目录项本身：删除一个符号链接只删链接，不删它指向的东西。家目录本身不能删除、改名。

"文件"App 看到的文档标志按路径的字面给出（家目录里面的能写、能删），真正的检查在原生库里，经由符号链接出去的会在操作时失败。

### 与运行中的内核

- 仓库的修改都是事务，另一个连接改了之后，内核的缓存经由共享的提交计数器作废（§8.1），终端里马上看得到"文件"App 新建、删除、改名的东西。
- 写的是宿主上的 object 文件本身（交出读写的 fd，截断时先截断，追加时以 `O_APPEND` 打开），普通文件的大小、修改时间本来就取自 object，内核也马上看得到。
- 删除内核正打开着的文件，与 guest 自己删一样：object 删掉，打开着的 fd 照样能用，inode 的记录留到下次开机清理。
- 改了之后通知"文件"App 重新列那个目录；删除、改名、移动之后撤销原来那个文档的授权（`revokeDocumentPermission`）。

追加原来打算在 Kotlin 里拿到 fd 之后用 `Os.fcntlInt` 设 `O_APPEND`，lint 指出它要 API 30（minSdk 是 29），改成原生库打开 object 时就带上（新的 `Store::open_object_append`）。

## 测试

- 内核层（`cargo test`）新增 `changes_stay_inside_the_top_directory`：新建时换名字、不合法的名字、属主和权限位，写、追加、截断，家目录外面和经由符号链接出去的都是 EACCES，删除符号链接只删链接，改名不覆盖、移动、删除整个目录树。
- 仪器测试新增 `documentsWriteInTheHomeDirectory`：在运行着的内核里建账号 bob、设成登录账号，经由 `DocumentsContract` 和 `ContentResolver` 新建、写、改名、移动、删除，内核里马上看得到、属主是 bob，改不了的都失败。上一轮 `documentsShowTheHomeDirectory` 里"以写的模式打开失败"那条改成"整个系统那个根里的 `/etc/motd` 不能写"：家目录现在能写了。在 Pixel 4a（API 34）的模拟器上通过。
- 手动（模拟器上的"文件"App）：从"下载""复制到…"tuxport、新建文件夹、删除，终端里都看得到。

## 推迟项

- "文件"App 做的修改不产生 inotify 事件，guest 里监视着的程序（编辑器、构建工具的 watch）不知道。→ 已改：交给运行中的内核报事件，写的文件在对方关闭时报 `IN_MODIFY`、`IN_CLOSE_WRITE`（[M9："文件"App 与 guest 双向的通知](201-documents-notify.md)）
- 不检查 guest 的权限：家目录里属于 root 的文件也能改、删（这台设备的用户在终端里本来就能 `doas`）。
- 覆盖正在运行的程序不像 guest 里那样是 ETXTBSY。
- 只能改家目录：要放到别处（`/opt`、`/srv`）得先复制进家目录，再在终端里移过去。
- 同一个根里的复制没有原生实现，也是"文件"App 一块一块读写；大目录树复制进来、删除都是一个文件一个事务，很多小文件时慢。
