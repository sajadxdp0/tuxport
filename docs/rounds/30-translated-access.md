# M9 之前：翻译后代码里的访存（2026-10-26）

起进程的开销做到原生的 1.05–1.4 倍之后，回到计算为主的负载：gcc 编译 `lvm.c` 2.2 秒（原生 0.69 秒），python 循环 0.70 秒（原生 0.15 秒）。

## 时间花在哪里

按用途给翻译后代码的样本归类（`target/mem/tagsrun.sh`，带标记的 `dbt.c` 是 `target/mem/dbt.c.tagged-r4`）：

| 负载 | 翻译后代码占比 | TLB 检查 | 块入口 | 地址计算 | 原样拷贝 | 访问本身 | 其余 |
|---|---|---|---|---|---|---|---|
| gcc | 76% | 32% | 12% | 12% | 10% | 7% | 返回 4.7%、链接 3.7%、跳转缓存 0.9% 等 |
| python 循环 | 92% | 56% | 5.7% | 4.9% | 1.9% | 7.6% | 跳转缓存 7.8%、返回 7.0% 等 |

cc1 的剖析很平，最热的块只占 0.6%。翻译后的代码里每次访存 8 条宿主指令，追指针的读要多等约 7 个周期（取下标、算表项地址、取表项）。

## 量过、没有改的

- 块入口的 kick 检查换成两条 NOP，gcc、python 都没有可测的变化：块入口的样本是跳进新块时前端的开销，不是这两条指令。
- 每个块后面补 128 个字的 NOP（代码量多一倍以上）只让 gcc 慢 4%–6%、python 慢 3%：在这台宿主上指令缓存不是主要因素（手机的 L1 指令缓存小得多，可能不同）。
- 数据 TLB 加到 8192 项没有变化；减到 2048、1024 项时 python 循环从 0.70 秒慢到 1.0 秒（冲突）。表项本身的缓存占用不是问题。
- 同一会话里第二次编译 `lvm.c` 从 2.24 秒降到 2.0 秒：cc1 有 13 万个块、46 MB 代码，超过翻译池保留的上限，第二次从翻译模板拷贝。放宽上限让池里留下它，第二次也是 2.0 秒，拷贝模板不贵，没有改。

## 做法

- **最后一个字节的地址直接从基址算**（§4.2）：原来 `T0 = 基址 + 偏移`、`T1 = T0 + 字节数 - 1`、再取下标，下标要等 T0；现在 `T1 = 基址 + (偏移 + 字节数 - 1)` 与 T0 并行，指令数不变。
- **地址已知的访问**（§4.2）：翻译时跟踪 ADR/ADRP 设下的常数（以及在它上面加的立即数），以它为基址的访问表项位置是常数。tag 仍和真实地址比较，跟踪错了只是多走一次回填，不会访问错。

## 结果

测量（3 轮交替）：python 循环连跑 3 次 2.17 → 2.09 秒（−4%）；gcc 冷编译 2.21 → 2.18 秒，同一会话里第二次 1.99 → 1.96 秒；python 启动加循环 1.40 → 1.39 秒。

## 测试

lockstep 新增 pc_page 类：ADRP 算出本页的地址（可能再加立即数）再读本页，与硬件一致。第一版生成器给 LDP 的偏移超出了 7 位立即数，编码回绕，读到了两边不同的字。lockstep 查不出取错表项：被测的 guest 地址就是原生一侧的宿主地址，取错表项时读到的也是一样的内容（去掉已知地址那条路径的 tag 比较照样通过），要靠差分测试。

- LTP 的 times03 这次看到进程的用户态 CPU 时间倒退了一个滴答，这一轮没有碰 CPU 时间的统计，记下待查。→ 已查明并修好：内核态时间按滴答取整，跨过一个滴答时用户态时间（总数减去内核态）倒退（M9 之前：CPU 时间不倒退）

## 推迟项

- 剩下的差距在软件 MMU 的检查本身：每次访存 8 条宿主指令，追指针的读多等约 7 个周期，按检查的写法已经试过的变体（上一轮和这一轮）都没有更好的。要大幅减少，只能不查表：给每个 guest 进程一段宿主地址空间，guest 地址加一个常数就是宿主地址，检查变成一次比较。Android 的 GKI 内核用 39 位地址空间（512 GB），容不下几个进程各一段；16K 页的设备上 4K 的 guest 页没法逐页映射；还要把 mmap、mprotect、写时复制都同步到宿主页表，宿主缺页要能精确地恢复到 guest 指令。代价很大，没有做。
- 块入口、返回、链接合计约占翻译后代码的四分之一：可以把无条件跳转的目标、调用之后的落点接着翻进同一个块（超级块），少跳一次，组内共用检查的机会也多一些；影子返回栈的指针在内存里，调用和返回之间经过存储转发串成一条链。→ 试了超级块，没有收益，没有采用（M9 之前：超级块的实验）
- times03 偶发的 CPU 时间倒退。→ 已修好（M9 之前：CPU 时间不倒退）
