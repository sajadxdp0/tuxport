# M9 之前：跳到未对齐的地址（2026-10-30）

为下一轮（[有 JIT 代码的进程也共用翻译](115-shared-with-jit.md)）读跳转缓存的代码时发现的：guest 的 `br`、`blr`、`ret` 跳到地址 1 时，Tier 1 跳进了 NULL。Linux 上这是取指时的对齐错误（SIGBUS，`BUS_ADRALN`，pc 是 1），Tier 0 也是这样报告的；Tier 1 在宿主上 SIGSEGV：tuxport-run 报告内部错误（引擎里的宿主故障），以 SIGSEGV 结束这个 guest 进程，信号处理函数没有机会运行，这个实例的翻译也作废了。

## 原因

原因是两处用同一个未对齐的值 1 当"不会被查到"的标记：

- 跳转缓存的空项是 `{pc = 1, code = NULL}`。翻译后的间接跳转按目标的第 2–13 位取一项，pc 相同就直接跳往 code，不看对齐：目标是 1 时取的正是第 0 项，第 0 项空着就跳往 NULL。跳到 2、3 这些别的未对齐地址时取到的空项 pc 对不上，照常查表，所以只有 1。
- 翻译表里作废的块留下的墓碑是 `{pc = 1, code = 作废块的入口}`。查表例程和分发器查 1 时，从第 0 个位置往后找，路上有墓碑就"找到"了作废的块：它的入口跳往转发桩，按原来的 pc 退出，guest 接着执行那个块原来的代码，而不是收到 SIGBUS。

## 做法

- 跳转缓存第 i 项空着时的 pc 是 `((i + 1) mod 4096) << 2 | 1`：未对齐，而且按它算出来的下标是下一项，那一项的 pc 又是另一个值，所以跳到哪里都不会命中空项。翻译后的间接跳转不用多一条指令。
- 查表例程和 `table_find` 先排除未对齐的 pc：交给分发器，由 Tier 0 报告对齐错误。这是没命中跳转缓存之后的路径，多两条指令。

影子返回栈的空项本来就跳往一个查表的例程（`rs_miss`），不是 NULL，`ret` 到 1 时经由它走到上面的查表。

## 测试

- 单元测试 `branches_to_unaligned_addresses_fault`：先让墓碑落在查 1 时开始找的位置，再用 `br`、`blr`、`ret` 跳到几个未对齐的地址，都要像 Tier 0 一样报告对齐错误。
- 差分测试 `edge-cases` 加了一段：经由函数指针调用和 `ret` 跳到未对齐的地址，与原生一样收到 SIGBUS（`BUS_ADRALN`）。
