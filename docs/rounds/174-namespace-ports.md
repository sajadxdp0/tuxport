# M9 之前：各个网络命名空间的端口互不相干（2026-11-01）

容器网络四步做完之后，审推迟项时实测发现一个更严重的问题：外层命名空间监听 0.0.0.0:P 时，新的网络命名空间里再绑同一个端口是 EADDRINUSE（原生上两个命名空间互不相干）。原因是外层的 socket 在宿主上绑的是通配地址，而新命名空间的绑在 127.a.b.1 上，宿主认为两者冲突。podman 占端口的 socket 和 docker-proxy 都在容器起来之前就绑好了，所以 `-p 8080:8080`、`-p 3000:3000`、`-p 5432:5432` 这类内外同端口的发布，容器里的服务都起不来。前两轮的普查和测试都用 8080:80，正好避开了。

同一轮还修了两处由同一个原因引起的不一致（[第 171 轮](171-netmap.md)、[第 173 轮](173-port-forwarding.md)的推迟项）：

- 连到别的命名空间里没人监听的端口时，会被外层监听通配地址的 socket 接走，挂住；原生是 ECONNREFUSED。
- 容器里只绑 127.0.0.1 的服务，别的容器也连得到；原生连不到。

## 做法

- **新命名空间里的端口在宿主上另选**（`portmap::bind_any`）：
  - 新的网络命名空间里显式绑的端口（低端口也一样），宿主上一律让宿主分配一个，登记在低端口映射的那张表里（[第 156 轮](156-low-ports.md)），按（命名空间、协议、guest 端口）查。
  - 这样宿主上不占这个端口：外层、手机上别的 App、别的命名空间都照样绑得了它，先后顺序无关。
  - 同一个命名空间里再绑同一个端口用同一个宿主端口，所以 guest 自己的冲突照常是 EADDRINUSE，`SO_REUSEPORT` 照常可以。
  - 别人连这个命名空间里的端口时按表换成宿主端口；getsockname、accept、recvfrom、`/proc/net` 照低端口那样换回 guest 的端口。
  - 低端口在新命名空间里不再按偏移选宿主端口：别的设备本来就连不到它们，开机时的命名空间里的低端口因此总能拿到可以预料的宿主端口。
- **新命名空间里的监听登记在命名空间里**（`netns::add_listener`、`netns::listening`）：
  - 新的网络命名空间里 listen 的 TCP socket，记下 guest 的端口、绑的 guest 地址（通配地址；虚拟地址；127.0.0.x；AF_INET6 的 ::1）、地址族、`IPV6_V6ONLY`，socket 关掉时去掉。
  - TCP connect 的目的地（OUTPUT、PREROUTING 的 nat 之后）在一个新的网络命名空间里时，那里要有对得上的监听，不然就是 ECONNREFUSED。对得上的规则与 Linux 一样：0.0.0.0 接受 IPv4 的；`::` 接受 IPv6 的，没设 `IPV6_V6ONLY` 时也接受 IPv4 的；绑了地址的只接受发往这个地址的。这也包括连自己命名空间里的 127.0.0.1 和 eth0 地址。
  - 宿主上新命名空间的监听都在它的回环地址上，外层监听通配地址的 socket 也盖住这些地址，所以不能交给宿主去连。

## 测试

- 新的差分测试组 `nsports`（原生一侧是特权容器；一个 bridge 上挂着 A、B 两个命名空间）：外层和 A 先后绑同一个端口之后谁连得到谁、回答的来源，没人监听的端口，只绑 127.0.0.1、只绑 eth0 地址的服务，A 里自己的冲突和 `SO_REUSEPORT`。两个执行层下都与原生逐字相同。单元测试测 `portmap` 的 `bind_any` 和 `netns` 的监听登记。
- `portfwd` 里 `iifname != "br0"` 的规则改成 `iifname "eth9"`：tuxport 假设外面来的连接从宿主上第一个接口进来，原来的规则对它成立，外层 8081 的监听交给了转发线程，A 的连接被它接走，以前碰巧是 guest 先 accept 才通过（上一轮的推迟项）。
- 实测：podman 起 `-p 8080:8080` 的容器，从 tuxport 里面和外面连都拿到了页面；原来容器里的服务绑不上。

## 推迟项

- 同一个新命名空间里，一个端口不能既绑 127.0.0.1、又绑 eth0 的地址（Linux 可以）：两者在宿主上是同一个回环地址，映射按（命名空间、协议、端口）只有一个宿主端口。
- 只对 TCP 查监听：UDP 发往没人绑的端口、只绑别的地址的端口，照样交给宿主，可能被外层绑通配地址的 UDP socket 收到（Linux 上被丢掉，连接了的 socket 下次收发得到 ECONNREFUSED）。 → UDP 也登记、没人绑的悄悄丢掉（M9 之前：网络命名空间的 sysctl 补齐、UDP 也查有没有人绑）；仍收不到 ECONNREFUSED
- 新命名空间里的低端口不再按偏移选宿主端口，内核日志里也不再写"port 80/tcp is … on the host"：它们本来就只在 tuxport 里面连得到。
